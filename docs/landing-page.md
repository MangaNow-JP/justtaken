# JustTaken LP

https://justtaken.app/ に、承認されたデザインv2をもとにしたLPを公開。白い余白、深緑とライム、実写の写真を使い、撮影アプリとSNSの世界観を中心に構成した。アプリ自体は開発中として案内する。

## 配信と編集

- 正本：`workers/api/public/`。HTML・CSS・JavaScriptの静的構成。追加のWebフレームワークやビルドサービスは不要。
- Workers Static Assetsで既存の `justtaken-api` と同じ独自ドメインに配信。
- `/v1/*`、`/public/*`、`/.well-known/*`、`/verify` と検証用JS、`/health` は常に既存Workerへルーティングする。
- `/terms`：利用規約。`/privacy`：プライバシーポリシー。`/credits`：写真とフォントの出典。[規約・ポリシーの内容と版管理](legal-pages.md)を参照。
- 写真はUnsplashの実写素材。アプリ利用者の投稿や撮影認証済み原本としては表示しない。最適化WebPはLPだけで使用し、撮影原本の保存方式を変えない。
- 日本語フォントはNoto Sans JPの必要文字を含む可変フォントを同梱。外部フォント・広告・解析のリクエストはない。文字を追加する場合はフォントの文字範囲も更新する。
- CSS/JS/フォントを変更したらHTML内のバージョン付きURLも更新する。画像名を変えた場合は `src` と `srcset` を確認する。

起動は `npm run setup:local` → `npm run api`、URLは `http://localhost:8787/`。公開は既存の `npm run deploy:production`。静的ファイルの変更もこのコマンドで反映する。`npm run verify:production` でLPと既存APIを28項目検査する。

## 先行案内の受付

`POST /public/early-access` は、メールアドレス・端末の種類・明示的な同意・空のhoneypotを受け付ける。正規originのチェック、4KiBの本文上限、入力検査、1 IPあたり6 requests / 60秒の専用rate limitを設定。一般APIの120 requests / 60秒も適用する。メールアドレスを取得する公開APIは作らない。

D1 migration `0006_early_access.sql` で `early_access_registrations` を追加。メールアドレスは小文字化して重複を防ぎ、同意の版・登録日時・180日後の期限・取り消しトークンのSHA-256を保存する。重複登録で元の同意期限やトークンを更新しない。応答は重複の有無によらず同じ形式。

登録者は完了画面からテキストの控えを保存できる。取り消しURLの秘密トークンはfragment内に置き、ページ表示後にアドレス欄から取り除く。取り消し操作時のみ `DELETE /public/early-access` のJSON本文で送信する。DBには平文トークンを保存しない。同じトークンで繰り返し取り消しても成功する。初回の控えを紛失したときの本人確認・再発行は未実装のため、画面で保管を案内する。

期限切れの登録は既存の5分cronで削除する。外部時刻認証の再試行と併行して実行する。受付と削除は実装済みだが、**案内メール送信・配信停止付き配信基盤・管理画面は未接続**。公開案内を送る前に、保存期限内の同意がある登録だけを対象に、送信ドメイン認証・配信停止導線・運営連絡先を含めた配信手段を整える。登録だけで確認メールを送ったとは表示しない。

`/#proof` を、撮影証明書の見本と「原本に証明を結び付ける」「投稿せず保存する」「相手が照合する」の3点を示す構成に更新。実際の `/verify` にリンクする。見本は `SAMPLE` と明記し、素材写真の検証結果や実際の署名として扱わない。証明の範囲を常時表示し、AI画像を映した画面・印刷物の再撮影などの限界を開閉して読めるようにした。FAQにもAI生成判定との違いを記載。撮影認証・署名・原本処理の変更はない。
